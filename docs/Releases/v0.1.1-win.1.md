# v0.1.1-win.1 — Windows release verification (media enabled)

Native Windows 11 x64 build for **2 × Tesla V100-SXM2-16 GB (TCC, NVLink)**, tensor-parallel
(`--tp 2`), CUDA 12.8, built with `NINFER_STUB_MEDIA=OFF`: image and video prompts and HTTP(S)
media acquisition are compiled in rather than stubbed out. This page records what was verified for
the release and where the raw evidence lives; [docs/windows.md](../windows.md) documents the build,
the verification gates and the known limitations.

## Build

Built on 2026-10-20 from the repository at the tagged commit with
`scripts\windows\fetch-media-deps.cmd` + `scripts\windows\configure-media.cmd` +
`NINFER_BUILD_DIR=build-win-media scripts\windows\build.cmd ninfer ninfer-serve`,
`NINFER_BUILD_JOBS=6`, CMake `Release`, `NINFER_STUB_MEDIA=OFF`, `BUILD_TESTING=ON`,
`CMAKE_CUDA_ARCHITECTURES=70`.

| Artifact | Size | SHA256 |
|---|---:|---|
| `ninfer.exe` | 343,806,464 B | `0d06580389e4d244af3d78693d5b04b3ecef527638363f137963f2f35235f613` |
| `ninfer-serve.exe` | 344,689,664 B | `1e66791a5348b5fc847150c62ff4ad5b0faa774d23dd28c8086ce2e2a892f3d4` |

Toolchain: CUDA 12.8.0, MSVC 14.38.33130 (Visual Studio 2022 17.8), NVIDIA driver 576.57.
FFmpeg 8.1 (`lgpl-shared`, BtbN) and libcurl 8.11.1 built from source against Schannel.

Unlike `v0.1.0-win.1` these executables are **not** self-contained: they import
`avcodec-62`, `avformat-62`, `avutil-60`, `swscale-9`, `swresample-6` and `libcurl`, so the DLLs in
the archive must stay next to them. The asset is a single zip for that reason; the same archive was
extracted to an empty directory and `ninfer.exe --help` ran successfully there, which is the
self-containment check that matters for a consumer. The CUDA runtime is still linked statically, so
no `cudart64_*.dll` is required.

## What changed relative to v0.1.0-win.1

- `NINFER_STUB_MEDIA=OFF` on Windows: `cmake/FindFFMPEG.cmake` (upstream assumes pkg-config or a
  vcpkg config package), `scripts\windows\fetch-media-deps.cmd` (FFmpeg dev package + libcurl from
  source) and `scripts\windows\configure-media.cmd` (`build-win-media`, separate from `build-win`).
- `src/product/media_acquire/acquire.cpp` ported to Winsock (`winsock2.h`/`ws2tcpip.h`, one-shot
  `WSAStartup`, `gai_strerrorA`) and to explicit UTF-8 `std::filesystem::path` construction;
  `relative.native().starts_with("..")` compared `std::wstring` with `char*` and did not compile.
- Media runtime DLLs staged next to both executables after linking.
- The host test suite builds on Windows for the first time: `<unistd.h>`/`<sys/wait.h>`,
  `std::aligned_alloc`, `constexpr std::sqrt`, `getpid`, and MSVC's ANSI-codepage source decoding
  (now `/utf-8` for every test target) each blocked a target.

## Text regression

Same artifact, text-only prompt, greedy, 4,096-token window: **40.33 tok/s decode, 190.59 tok/s
prefill**, answer `2, 3, 5, 7, 11`. v0.1.0-win.1 measured 39.2 tok/s decode / 178.9 tok/s prefill on
the stub build, i.e. enabling media costs nothing measurable on the text path.

## Unit test suite

`ctest` over `build-win-media`: **133 registered, 121 pass, 12 fail, 1 not built**. The full list
with signatures is in [docs/windows.md](../windows.md#unit-test-suite-ctest-on-the-media-tree);
summary:

- `ninfer_media_decode_test` (the swscale width-tight RGB24 reproducer from upstream issue #20) and
  `ninfer_vision_attention_test` pass.
- 10 failures exit with `0xC0000409` and no output. The same fast-fail code and offset already exist
  in this tree's WER archive for the pre-media `ninfer-compat.exe`; 12 other tests in this group
  failed only because `TMP` was not writable and pass with a valid `TMP`.
- 2 failures are numeric/capability assertions (`relative_l2` comparison, `NVFP4 A4 execution
  requires an sm_120a GPU`, `bad allocation` on oversized fixtures).
- `ninfer_qwen3_8_27b_dflash2_real_test` is not built: the portable CUDA toolkit has no
  `cuda_profiler_api.h`.

None of the 12 touches the media path.

## Limitations

- **Requires the bundled DLLs.** Copying only the executables out of the archive will fail to start;
  the FFmpeg/libcurl DLLs must sit beside them. For a text-only single-file binary use
  `v0.1.0-win.1`, which is built with `NINFER_STUB_MEDIA=ON`.
- **`SystemMonitor` is empty.** Its host/GPU sampling is `/proc`-based on Linux and returns no rows
  on Windows; the monitor page has no data. Serving is unaffected.
- **No independent cross-platform numeric baseline.** These binaries have not been numerically
  cross-checked against a Linux build on the same artifacts; the gates above verify behaviour, not
  cross-platform bit-exactness.
- **12 of 133 unit tests fail** with the signatures above; the media, text, serving and reader paths
  are covered by the gates that pass.
