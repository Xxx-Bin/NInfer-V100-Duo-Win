# v0.1.1-win.5 — CI-built Windows release (media enabled)

Native Windows x64 build for **2 × Tesla V100-SXM2-16 GB (TCC, NVLink)**, tensor-parallel
(`--tp 2`), CUDA 12.8, `NINFER_STUB_MEDIA=OFF`: image and video prompts and HTTP(S) media
acquisition are compiled in rather than stubbed out. Unlike `v0.1.1-win.1` this release was produced
by `.github/workflows/build-windows.yml` on a hosted runner, not on the V100 machine, and was then
accepted on the target hardware before it was published as a real release.
[docs/windows.md](../windows.md) documents the build, the verification gates and the known
limitations; the release flow (test build → acceptance → promotion) is described in
[Release flow](../windows.md#release-flow).

## Provenance of the published archive

The run first published `test-v0.1.1-win.5` as a prerelease. After the acceptance checks below the
release was promoted in place through the Releases API: the tag was renamed to `v0.1.1-win.5`, the
prerelease flag was cleared, both assets were renamed, and the sidecar was rewritten to name the
renamed archive. The archive bytes are the ones the run built and the ones the acceptance run used -
the digest above is unchanged from the test release.

## What this release does not verify

- **Correctness beyond the smoke set.** CI has no GPU, so the run proves configure/compile/link/
  package only; the tables above are a local acceptance run, not a test suite. The `ctest` evidence in
  [v0.1.1-win.1](../archive/superseded/2026-10-release-notes/v0.1.1-win.1.md) came from the same source tree built locally.
- **The CLI file-path media route.** The smoke went through `ninfer-serve` with data URIs and HTTP
  URLs; `ninfer.exe --messages <local path>` (and the non-ASCII path handling) needs the model
  reloaded on an otherwise idle GPU and was not re-run for this archive.
- **`raw.githubusercontent.com` from libcurl on this host.** That host timed out at the 5 s connect
  timeout although the same URL fetches in 0.2 s from PowerShell; two other HTTPS hosts worked
  through the same libcurl, so it is a host/CDN connectivity condition rather than a build defect.
- **Text and long-context throughput.** No new measurement; use the numbers in
  [v0.1.1-win.1](../archive/superseded/2026-10-release-notes/v0.1.1-win.1.md) for this tree.
