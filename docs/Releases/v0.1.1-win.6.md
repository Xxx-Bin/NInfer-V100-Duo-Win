# v0.1.1-win.6 — CI-built Windows release (media enabled)

Native Windows x64 build for **2 × Tesla V100-SXM2-16 GB (TCC, NVLink)**, tensor-parallel
(`--tp 2`), CUDA 12.8, `NINFER_STUB_MEDIA=OFF`: image and video prompts and HTTP(S) media
acquisition are compiled in rather than stubbed out. Produced by
`.github/workflows/build-windows.yml` on a hosted runner, then accepted on the target hardware
before it was published as a real release. [docs/windows.md](../windows.md) documents the build,
the verification gates and the known limitations; the release flow (test build → acceptance →
promotion) is described in [Release flow](../windows.md#release-flow).

## Provenance of the published archive

The run first published `test-v0.1.1-win.6` as a prerelease. After the acceptance checks below the
release was promoted in place through the Releases API: the tag was renamed to `v0.1.1-win.6`, the
prerelease flag was cleared, both assets were renamed, and the sidecar was rewritten to name the
renamed archive. The archive bytes are the ones the run built and the ones the acceptance run used -
the digest above is unchanged from the test release.

## Known issue: one degenerate 32k answer

The first 32k run of this acceptance session, started immediately after the 16k process had exited,
generated sixteen `!` tokens instead of the code. Five later 32k runs (one eager, four graph) and
then ten consecutive repeat runs all returned `918273`, so the observed rate is 1 in 15. The failing
run is indistinguishable from the passing ones in its summary: the same 3.81 GiB free after startup,
512/512 KV page groups, 261.01 MiB workspace peak and a normal 956 tok/s prefill. GPU state was idle
before each start; the failing run was the only one launched without a pause after the previous
process. It is recorded here rather than dismissed because it is not yet explained.

## What this release does not verify

- **Correctness beyond the smoke set.** CI has no GPU, so the run proves configure/compile/link/
  package only; the tables above are a local acceptance run, not a test suite.
- **The CLI file-path media route.** Media was exercised through `ninfer-serve` with data URIs and
  HTTP URLs; `ninfer.exe --messages <local path>` (and the non-ASCII path handling) was not re-run
  for this archive. Long-context messages JSON is text-only.
- **A soak run.** The 10-minute soak recorded for `v0.1.1-win.5` was not repeated; the 32k repeat
  loop above (15 runs) is the only extended load.
- **Independent numerical baseline.** Graph/eager equality and correct answers are self-consistency
  evidence, not a comparison against an independent reference implementation.
- **Text and long-context throughput across the tree.** No new benchmark; the numbers above come
  from a single artifact and the acceptance prompts.
