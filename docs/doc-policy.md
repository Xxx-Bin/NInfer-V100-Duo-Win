# 文档适用性治理规范

本文规定本仓库文档的**适用范围判定**、**归档方式**与**过时标注格式**。它不定义任何产品、
模型或 Op 契约；那些仍由 `docs/maintainer/` 下的现行参考负责。本文只回答一个问题：
一份文档在当前构建（Windows 11 · 2×V100-SXM2 16 GB · NVLink · `sm_70` · CUDA 12.8 · TP2）
下还算不算数，以及不算数时怎么处理。

适用范围：`git ls-files "*.md"` 能列出的文件。`_ref/`、`_toolchain/`、`_scratch/`、`probe/`、
`.agents/worktrees/` 由 `.gitignore` 隔离，不属于本文管辖，也不参与任何文档索引。

`_scratch/` 内的过程材料（战役交接、尽调卡、规划、原始测量输出）**只以单一自包含记录**
进入版本控制：`docs/notes/v100-port-campaign.md`。该文件是 `record` 角色，只增不改地记录
已终结的判决；`_scratch/` 下的原始材料视为本地证据仓，不受版本控制，也不得被其他文档
作为判决依据引用。

## 1. 分类维度

两个维度，不要混用。

**维度 A — 适用性**（决定去留，五值互斥）

| 值 | 含义 |
|---|---|
| `active` | 声称的适用条件覆盖当前构建 |
| `inherited` | 上游场景（单卡 5090 / sm_120a / 双 3060 / 1M 上下文 / Linux 单机），当前构建不满足 |
| `superseded` | 被更新且覆盖同范围的文件或构建流程取代 |
| `planned` | 描述尚未实现的未来态，或迁移未完成的规范 |
| `record` | 一次性过程记录（release 验收、交接、探针实验） |

**维度 B — 角色**（只写进横幅，不进路径）

`contract` 契约 · `guide` 用户指南 · `reference` 参考 · `evidence` 测量证据 ·
`note` 工作笔记 · `index` 索引

> 角色不进目录，因为归档目录按**原因**组织更利于检索；按角色组织会让同一个文件在
> 移入/移出时反复改路径。

## 2. 判定标准

先跑四条硬规则，任一条命中即得结论；四条都不命中才是 `active`。

**R1 资源可满足性** — 文中结论能否在 2×16 GB / `sm_70` 下复现？
出现以下任一即判 `inherited`：上下文 ≥ 1M、单卡 32 GiB、sm_86 12 GB×2、CUDA 13.x
编译、无 NVLink 的 TP2 拓扑。

**R2 身份可加载性** — 文中 artifact identity 是否在本 fork 的编译面内？
面内只有 `qwen3_6_27b`、`qwen3_6_35b_a3b` 两个 Package（`qwen3.8-*` 是 27B Package 的
第二 identity，见 `src/targets/qwen3_6_27b/export/ninfer/targets/qwen3_6_27b/package.h`）。
面外的 identity 判 `inherited`。

**R3 被取代性** — 是否存在更新且覆盖同范围的文件？
release 链只认最新一版；平台指南只认 `docs/windows.md`。

**R4 一次性** — 文件名或首段含 handoff / probe / 交接 / 已作废，且无后续维护价值，判 `record`。

**两条禁止**（防止误伤）：

- **禁止只凭 mtime 判过时。** 时间戳只能作为佐证，必须同时指出取代者或矛盾证据。
- **禁止因为"出现过 5090"就归档。** `docs/maintainer/linear-benchmark.md` 提到 5090，
  但它定义的是与硬件无关的 benchmark 合同，判 `active`。判据是**声称的适用条件**，
  不是关键词命中。

## 3. 处置规则

判定之后按**入链数**选动作（入链数 = 其他被跟踪 md 中以 Markdown 链接指向本文件的个数）。
移动文件会断链，所以动与不动的分界是引用成本，不是内容好坏。

| 条件 | 动作 |
|---|---|
| `active` | 不动。索引里保留 |
| 非 `active` 且入链 ≤ 1 | `git mv` 到 `docs/archive/` 对应子目录，加横幅 |
| 非 `active` 且入链 ≥ 2 | **就地加横幅**，不移动。在索引里降级 |
| 文件内部只有部分段落不适用（混合体） | 拆段：不适用的段移入归档文件，正文保留并加指针 |
| 目录入口文件（`README.md`） | 永不移动，只加横幅 |
| **脚本写入的路径（生成物）** | 永不移动。移动会与新一次运行的输出错位；改为在文件内加横幅，并在目录加一行说明 |

> 最后一条是实测修正：`eval/results/{soak-1m,mtp3-1m,final-rerun,needle-1m}` 的入链数为 0–1，
> 按链接判据本可移动，但 `eval/run_*.sh` 把 `results_dir` 固定在这些路径下，移动会让归档件
> 与重新生成的同名文件并存。纯链接统计看不出这种依赖，判定时必须同时查脚本里的写入路径。

**归档目录布局**

```text
docs/archive/
├── README.md                       # 归档索引，一表全列
├── inherited-5090/                 # 上游单卡 5090 / sm_120a 场景
├── inherited-3060/                 # 上游双 3060 / sm_86 场景
├── superseded/<yyyy-mm>-<topic>/   # 被取代的文件组
└── records/<yyyy-mm>/              # 一次性记录
```

**保留期**

| 适用性 | 保留 |
|---|---|
| `inherited` | 永久。上游同步时需要逐条对照 |
| `superseded` | 永久。release 审计链的一部分 |
| `record` | 6 个月后评估删除；git 历史仍可追溯 |

**移动时必须同时做的事**

1. 横幅写在 H1 之后、正文之前（见第 4 节）。
2. 更新所有指向它的链接（入链 ≤ 1，改一处）。
3. 在 `docs/archive/README.md` 增加一行。
4. `docs/README.md` 的索引里删掉或降级。
5. 修正**被移动文件自身**指向外部的相对链接（每深一层就多一个 `../`），否则归档件入口即断。
6. 归档文件正文**零改动**；除第 5 条的路径修正外，不要顺手改内容，否则历史证据与原文脱钩。

## 4. 过时标注规范

横幅用引用块，固定五行字段，缺一不可：

```markdown
> **状态：已归档 · 不适用于当前构建**
> 归档：2026-10-24 · 归属：inherited-5090 · 角色：evidence
> 原文适用条件：单卡 RTX 5090（sm_120a）· CUDA 13.1 · 32 GiB · 无 NVLink 的 TP2
> 现行替代：[docs/windows.md](../../windows.md)
> 保留理由：TP2 transport 的推导过程仍是当前实现的来源，结论不适用
```

字段约束：

- **状态**只有四种写法：`现行` / `计划态` / `已归档` / `已作废`。
  `已作废` 仅用于同目录内被明确取代且无历史价值的文件（例如
  `profiles/bench/peak-27b-nvfp4/NOTE.md` 这种"请用 ../xxx"的转指针）。
- **归档行的日期 + 归属 + 角色**必填，归属取第 1 节维度 A 的值。
- **原文适用条件**必须是原文自己写的硬件/工具链，不是转述。
- **现行替代**必填。没有替代时写"无替代（能力未在本 fork 提供）"，并说明缺的是什么。
- **保留理由**一句话。写不出理由就是不归档，直接删。

`计划态` 用同一格式但状态改为 `计划态`，`现行替代` 改为 `目标态文件`：

```markdown
> **状态：计划态 · 不是当前实现映射**
> 记录：2026-10-24 · 角色：contract
> 目标态：迁移完成后的唯一实现，当前源码仍是旧结构
> 现行实现：[op-development.md](op-development.md) 与 `src/ops/`
```

禁止的写法：

- 只写"本文已过时"而不给替代 → 读者无法决策。
- 在正文中间插一段"注意：以下内容不适用" → 横幅只放顶部一处。
- 用删除线或注释掉旧内容 → 历史证据必须可读。

## 5. 索引规范

- `docs/README.md` **只列 `active` 与 `planned`**，按现有分区维护：用户指南 / 模型 artifacts /
  仓库内指南 / 维护者参考 / 计划中的工作 / 归档。归档项只在最后一块出现，且只指向
  `docs/archive/README.md`，不逐条列出。
- `docs/archive/README.md` 列全部归档项，一表四列：文件、归属、归档日期、替代。
- 索引里的链接必须可跳转。断链视同文档缺失：`AGENTS.md` 与
  `docs/maintainer/model-weight-execution.md` 都引用过并不存在的
  `docs/maintainer/engine-architecture.md`，这类引用必须在同一次改动里修掉
  （指向 `concurrent-inference-architecture.md`，或删掉该句）。
- 一个主题只允许一个现行权威。归档件不得在正文里自称"最新"。
