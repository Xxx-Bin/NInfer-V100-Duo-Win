# 事故：本机两次无 dump 硬挂（2026-10-25 04:11 / 04:39）

## 结论（先给判决）

**最可能是硬件层的总线/互联不稳（CPU 侧 WHEA 可纠正错误风暴），不是内存不足、不是编译配置错。**
编译把 8 个逻辑核压满 → 可纠正错误激增 → 累积后整机挂死（无 bugcheck、无 minidump，属"丢电/硬复位"型）。
仓储/临时目录都在 C:（ZHITAI SSD），不存在编译 I/O 落在老机械盘上的问题。

## 证据

### 1. 两次非正常重启，均无 dump

| 事件 | 时间 | 说明 |
|---|---|---|
| Kernel-General 12（开机） | 04:24:37 | 会话 A |
| Kernel-General 12（开机） | 04:44:51 | 会话 B |
| Kernel-Power 41 | 04:24:41 / 04:44:54 | "未先正常关机即重启" |
| EventLog 6008 | last-alive 03:47:30 / 04:24:54 | 挂死前最后一次存活戳 |
| BugCheck 1001 | **无** | 没有蓝屏 |
| C:\Windows\Minidump | **空** | 没有 dump |

`CrashDumpEnabled=7`、`AutoReboot=1` 均已开，仍然没有 dump ⇒ 内核没有机会写盘，
即机器是**硬挂/硬复位**（冻屏后人工复位，或掉电），不是软件崩。

### 2. WHEA 可纠正错误风暴（决定性证据）

`Microsoft-Windows-WHEA-Logger` Event 19，正文全部是：

```
由以下组件报告: 处理器核心
错误源: Unknown Error Source
错误类型: Bus/Interconnect Error
处理器 APIC ID: 7
```

近 7 天按天计数：

| 日期 | 数量 |
|---|---:|
| 10-18 | 1 |
| 10-19 | 22 |
| 10-20 | 1（Id=1 未纠正） |
| 10-22 | 6 |
| 10-23 | 3 |
| 10-24 | 1 |
| **10-25 03 时** | **42** |
| **10-25 04 时** | **55** |

03 时那 42 条正好落在 tilen256 首轮 configure+编译（03:05→03:21:50）期间；
04 时那 55 条落在 04:34→04:38:59，即 packet-allreduce 编译进行中（构建进度 212/450）。
两次挂死都紧随风暴峰值。

### 3. 崩溃与编译的对齐

| 时刻 | 在做的事 | 结果 |
|---|---|---|
| 02:52:52 | WHEA **Id=1 未纠正**，STORPORT，设备 `WDC WD5000BPVT-80HXZT1`（D: 盘） | 老机械盘 fatal 错误，一次，与 C: 无关 |
| 03:05→03:21:50 | tilen256 configure + 编译（-j4） | 完成，WHEA 42 条 |
| 03:23→03:34 | 增量编译 + 两次测量 | 完成 |
| ~04:11 | kv-vec16 编译（-j4） | **冻结**（日志停在 04:10:59）→ 04:24:37 重启 |
| ~04:39 | packet-allreduce 编译（-j4） | **冻结**（日志停在 04:39:26，212/450）→ 04:44:51 重启 |

唯一两次冻结都发生在 `ninja -j4` 满载编译中；GPU 空载（卡片 44W/40W）。

### 4. 排除项

- **内存压力**：当前空闲 24.8 GB / 31.6 GB，提交 8.8 GB / 52.1 GB，页文件固定 20 GB。不是 OOM。
- **磁盘**：C: 在 ZHITAI TiPlus5000 SSD，健康；D: 那块 WD5000BPVT 有过一次 fatal，但仓库不在它上面。
- **GPU 温度**：挂前 GPU 空闲 44/40 W、49/48 °C，无过热。

### 5. 旁证：两块 V100 当前协商在 PCIe 3.0 **x4**（上限 x16）

```
0, Tesla V100-SXM2-16GB, 03:00.0, gen 3 (max 3), width 4 (max 16), 49C, 44.45W
1, Tesla V100-SXM2-16GB, 05:00.0, gen 3 (max 3), width 4 (max 16), 48C, 40.08W
```

平台是 **Ryzen 5 3400G + TUF B450M-PLUS GAMING**（APU 只有 x8 显卡通道，4C8T）。
双 SXM2 走转接/PLX，主机侧只有 x4 —— 这种"边缘信号余量"正是 Bus/Interconnect 可纠正错误的高发配置。

## 已采取的处置

1. `_scratch/port-bat/build-port.sh` 编译并行度从 `-j4` 降到 `-j2`（可用 `JOBS=` 覆盖）。
   降低 8 核饱和 → 降低 SoC/IF 抖动概率。
2. 每次编译前不再并发任何 GPU 任务（原本就串行，现在保持）。
3. 本文件作为事故存档；后续若再挂，追加时间点。

## 需要用户侧（BIOS/硬件）处理的建议

按性价比排序：

1. **PCIe 相关**：BIOS 里把显卡链路降到 **Gen2**、关 ASPM、确认 Above 4G Decoding 开启；
   物理上重插 SXM2 转接卡/连接线、清金手指。x4 协商本身就说明链路余量不足。
2. **供电**：2× V100 SXM2 标称 600 W，确认电源 12V 余量与线材；用单卡跑一次重负载看是否仍挂。
3. **内存/SoC**：关闭 PBO/AXMP 超频，跑一次 MemTest86（≥2 轮）。Zen 的 Bus/Interconnect 错误常与 DRAM/SoC 电压边缘有关。
4. **BIOS/芯片组驱动**更新到最新（B450 + Raven Ridge 的 PCIe 兼容性补丁较多）。

## 对战役的影响

- 不影响已得结论（基线、tilen256 判定都已落盘）。
- 编译变慢约 1.7×（-j2 vs -j4），但 ninja 增量可续，冻结后重跑即可。
- 测量阶段 GPU 满负载是另一类负载（PCIe DMA 更大），**更可能触发同一问题**。
  若测量中挂死，优先按上表第 1 条处理链路。
